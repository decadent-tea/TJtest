巡检台：产品设计审查与整改结果

日期：2026-09-21。范围：全部应用路由、主要页面、共享组件、执行记录与流程及问题的数据关系、相关接口约束。先审查后实施；本轮仅修改前端及交互，不修改 API、数据库或采集、复检、分析业务规则。现有背景、菜单切换和按钮动态效果保留。

产品定位与推荐结构

这是本机单会话的 Web 体检工具：人工操作形成执行记录；记录保存为可复用流程；流程自动复检生成独立记录；规则及模型基于证据形成问题和报告。问题不是独立手工维护的业务实体，归档也不是独立业务模块。

菜单职责与路由调整判断
体检首页#overview：概览、最近任务、新建入口保留概览，避免重复建设独立报表管理模块。
执行工作台#workbench / #run/:id：人工录制与自动复检控制更名，覆盖两种执行模式；进入时自动定位活动任务。
流程库#flows：可复用步骤、变量、编辑与自动复检与执行记录分离合理：一个是模板，一个是某次实际结果。
体检记录#history / #archive；#record/:id/:tab：证据、分析、用例、导出归档收进同一模块。旧地址兼容；移除全局重复详情导航，保留局部页签和返回入口。
问题中心#issues：跨记录核查、处理状态、备注、证据定位维持跨记录视角；“查看证据”直接定位请求、日志或步骤。
模型与设置#settings：模型配置、连接测试、本机规则说明名称符合实际职责；未配置模型可从分析页进入并返回。

CRUD 与交互取舍

执行记录由真实执行产生，不增加手工新增、编辑原始证据或批量删除。归档可逆，彻底删除保留独立确认。流程继续从录制形成，保留编辑和版本生成；不引入另一套手工流程创建器。问题由规则和分析形成，提供查看证据、更新处理状态与备注；删除用于移除不应保留的问题，不代替解决状态。模型配置保留新增、编辑、启停、测试和删除，不额外复制一套配置入口。

长证据及分析结果使用详情页；同一记录的接口、日志、画面、分析使用页签。短创建表单与确认使用弹窗；流程编辑保留较大弹窗，补齐草稿保护。沿用已有按钮层级：核心执行主按钮、报告强调按钮、编辑与辅助按钮、危险确认红色按钮，不把所有操作升级为主按钮。

暂缓项与边界

  • P2：流程定位器 JSON、依赖 ID 仍偏技术化。已解决输入丢失和依赖校验，图形化依赖选择与分步编辑需要独立设计，避免一次改造扩大执行规则范围。
  • P2：前端主包仍有约 653 KB 的构建体积提示；未在本轮引入路由拆包，以免扩大与产品路径无关的变化。
  • 当前产品没有多用户权限模型，未凭空加入角色或无权限业务流程。接口拒绝及连接失败继续显示实际错误。
  • 未在真实业务目标上重跑复检、删除数据或发起模型分析；本轮不宣称完成外部系统业务回归。草稿刷新保护采用浏览器提示，不是离线自动保存。

最重要的改善：用户能沿“找到记录 → 定位证据 → 处理问题 → 回到原来的列表”连续完成工作；遇到失败不会丢掉输入，危险操作前能理解影响。
