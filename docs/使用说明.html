巡检台 · Web 体检工作室

首版使用说明 / v0.1.0 / 2026-09-17

这是一套本机运行的 Web 体检应用，已经实现人工录制、接口与日志采集、流程保存编辑、容错回放、模型 API 配置、AI 分析和报告导出。当前版本面向单个测试工程师使用。

一、启动

环境要求：Windows、PowerShell 7（pwsh）、Node.js 24 或更新版本。首次启动需要下载 npm 依赖和 Chromium。所有终端操作使用 pwsh。

pwsh -File E:\codexProject\TjTest\Start-Studio.ps1

启动后打开 http://127.0.0.1:4318/。运行终端需保持开启，按 Ctrl+C 停止服务。

开发模式启动：

pwsh -File E:\codexProject\TjTest\Start-Studio.ps1 -Development

开发模式管理页面为 http://127.0.0.1:5173/，API 地址为 http://127.0.0.1:4318/。修改代码时服务可能重新加载，录制前避免同时改后端文件。

二、开始体检

  1. 首页点击“开始新体检”，填写任务名称、工程名称、环境和实际工程地址。
  2. 点击“打开浏览器并录制”，在新打开的独立 Chromium 浏览器中登录工程并执行业务操作。
  3. 按业务模块执行查询、表单等操作，在工作台查看采集到的接口、Console 和页面异常。
  4. 切换业务模块时检查场景划分，必要时在工作台点击“新场景”人工标记。
  5. 完成后返回工作台，点击“结束录制”，进入体检记录详情查看操作与证据。
  6. 点击“保存为流程”，到流程库编辑步骤或点击“再次体检”。密码输入会被替换成 LOGIN_PASSWORD 运行变量，复检时需要重新输入。

三、使用公司工程

点击“开始新体检”，填写任务名称、工程名称、环境和完整 HTTP/HTTPS 地址。浏览器运行于本机，能够访问本机可访问的内网工程。系统使用新的浏览器上下文，需要重新登录。

按业务模块录制，尽量将查询、新增、告警、导出等独立流程划分为场景。页面导航、点击、文本输入、选择、勾选、快捷键、滚动及 iframe 操作保存为动作。多页面使用独立 pageId，回放按页签映射执行。

暂停是“暂停全部采集”，动作、网络及日志都会停止新增，并在时间线上记录空档。结束会等待部分在途采集任务写入；浏览器意外关闭或服务重启时记录为中断，已保存证据仍可查看。

四、编辑与复检

流程编辑器可以修改描述、模块、场景、动作类型、输入值、变量名、按键、页面文本断言、超时、定位器和依赖步骤 ID。保存生成新版本，历史运行绑定原版本。

变量支持 {{变量名称}}，也可以在步骤中直接配置变量名。执行时从弹窗传入，运行结束清空，不保存输入的运行凭据。测试数据中的业务名称、日期和环境地址可通过变量替换。

定位器为 JSON 数组，例如：

[
  { "kind": "testId", "value": "search-button" },
  { "kind": "role", "value": "button", "name": "查询" },
  { "kind": "css", "value": "#query" }
]

依次寻找唯一匹配的控件。无唯一匹配时记录失败，不任意选一个。当前不启用自动坐标点击；记录坐标用于查看证据。

“失败后尝试下一步”适用于独立读取动作；“关键步骤：失败后阻塞本场景”适用于提交和重要前置。步骤依赖必须指向前面的步骤。关键步骤失败后跳过同场景剩余步骤，继续下一场景。建议在独立场景前添加入口导航，使页面可以恢复。

状态含义
已录制记录到人工操作，不代表业务验证通过。
执行完成动作成功执行，业务结果需结合证据确认。
断言通过配置的可见文本断言成立。
执行失败定位、操作、等待或断言失败。
前置阻塞依赖步骤或场景关键步骤失败，因此未执行。
已跳过步骤在流程中关闭，不执行。

有副作用的提交不自动重试，检查点不会回滚服务端数据。首版不自动提取响应 ID，请将关联数据作为运行变量维护；测试数据清理需显式配置操作。

五、接口与异常证据

保留请求 URL、方法、查询参数、脱敏请求头与正文、响应头与 JSON/文本正文、HTTP 状态、耗时和网络失败。初始化和静态资源也保留。接口描述依据菜单、标题和动作生成，归属显示置信度，目前是时间与页面上下文的规则推断，复杂异步场景需人工核对。

工作台选择左侧操作，再切换“仅所选步骤”，联动查看接口与日志。点击接口打开参数与响应。截图是动作后的可用画面，密码框被遮盖。录制器不使用原始 Trace/HAR 包，避免这些文件另外持久化凭据。

检测规则包括 HTTP 4xx/5xx、网络失败、console.error、页面异常、未处理 Promise rejection、警告、慢业务请求和回放失败。HTTP 错误需要人工判断是否属于预期负向测试。首版不把不同工程的业务成功码写死为 code=0，也尚未提供工程级成功码规则编辑。

六、接入 AI

  1. 系统维护 → 添加模型。
  2. 选择 DeepSeek、Qwen、GLM 或 Custom；填写实际 Base URL、API Key 和模型 ID。
  3. 设置超时和输出 Token 上限，保存并“测试连接”。企业代理或特殊服务可以填写对应兼容地址。
  4. 结束体检后，工作台 → 分析与用例，选择模型并发起分析。

API Key 使用 AES-256-GCM 加密保存，页面不回显原文。密钥解密所需的本机文件为 data/.encryption-key，不应与普通报告一起分享。

AI 接收脱敏后的步骤、异常、接口响应摘要和错误日志；不发送截图。分析提示词要求模型依次审计业务流程、操作与接口链路、HTTP 200 中的业务失败码、前端异常、数据与稳定性、安全直接证据和可测性缺口。每项发现必须给出观察事实、业务影响、复现路径、候选原因、处置建议、验证步骤、严重级别、置信度及真实证据 ID。模型不得把 HTTP 2xx 或操作已执行解释为业务通过，不得猜测未出现的漏洞和根因。结果经过 JSON Schema 和本批证据 ID 校验；无法验证的引用和发现会被丢弃。AI 整理用例标题和具体可观察预期，推断内容标记待人工确认，实际结果与状态只来自运行记录。

长时间录制无需拆分：系统按操作顺序整理全部步骤、业务接口、失败资源和所有日志；成功静态资源只计数；同接口、同响应结构的正常调用和重复日志合并为代表分析项，异常按内容分组；模型引用会扩展回全部本机原始证据 ID。系统最多并行处理 3 批，再生成带覆盖范围、风险数量、涉及模块和优先核查项的整次摘要。每次模型调用限制输入大小和详细用例数量，模型上下文不足或输出截断时自动缩小当前批次。长字段采用摘要，完整证据仍保留本机。页面显示已完成批次、原始证据条数、合并后分析项，以及每个活动模型请求的等待时间、尝试次数和流式接收字符数；可以主动停止分析，已完成检查点不会丢失。Qwen 混合思考模型默认关闭思考模式以降低延迟和 Token 消耗，可以在模型配置中按需开启。AI 二次综合摘要默认关闭，系统直接从已校验的问题项生成结构化摘要，省去额外模型调用；需要模型润色跨批摘要时可以开启。已完成批次持久保存，限流和暂时故障会自动重试；仍失败或服务重启后，使用相同模型配置点击“继续未完成分析”，可接着处理，无需重新录制。分析规范升级、证据、模型或输出上限改变时会重新分析；只更换同一配置的密钥或超时，可继续已完成进度。综合摘要调用失败时保留全部批次摘要、问题明细和用例，并在报告中说明。录制越长，分析耗时和 API 费用相应增加。真实厂商 API 需配置有效账号测试；开发验证使用本地模拟模型服务，不代表已验证你的厂商账号。

七、报告、归档与备份

体检记录详情可下载 Word DOCX 报告和 XLSX 用例。用例列出操作、接口、Console、是否通过、问题描述和解决方案；报告以表格呈现执行总数、有效接口调用总数、Console 总数和通过率，并沿用模板的目录、标题和段落格式。所有报告和电子表格文本采用黑色宋体。

体检记录中可以归档；历史档案中可以移出归档。归档是保留标记，尚未实现独立签名或不可修改的归档包。数据文件位于 data/studio.sqlite，附件位于 data/artifacts，模型密钥文件位于 data/.encryption-key。备份请先停止服务，然后整体备份 data 目录。

八、已验证与当前边界

运行集成验证：

Set-Location E:\codexProject\TjTest
npm run verify
npm run build

验证使用独立的 output/verification 数据目录，不污染正常体检记录。覆盖登录与密码脱敏、中文输入、查询与保存、接口错误和页面异常、暂停恢复、流程回放、失败依赖与后续场景继续、文本断言、模拟模型 HTTP 调用、非法证据拦截及 Excel 字体。

首版不承诺通用支持 Canvas/WebGL、closed Shadow DOM、复杂拖拽、悬停触发流程、任意工业控件、验证码自动处理。操作系统地址栏逐键输入不采集；导航结果会记录。文件上传只录制文件名，回放需显式配置本机测试文件变量。原生浏览器对话框可以在浏览器或工作台确认、取消，选择结果会录制；回放按录制结果处理，未录制的额外对话框默认取消并记录说明。

WebSocket 保存通道、收发计数和限额消息采样（最多 100 帧，每帧 1000 字符）；SSE 消息采样在日志中（每连接最多 500 条，每条 2000 字符）。WebSocket/SSE 采集已在受控工程验证；Worker/Service Worker 和所有厂商系统的完全覆盖尚未专项验证。服务器内部调用和异常栈需要后续日志/APM 接入。截图可能含业务数据，需要按工程选择合适测试数据。

当前为单机、单会话应用，绑定 127.0.0.1，未提供团队账号权限、集中执行器、远程浏览器嵌入、自动保留清理或全系统覆盖基线。接口归属、复杂控件和业务断言仍需在公司典型测试工程上做真实适配。

server/export.ts      黑色宋体 XLSX 导出
shared/types.ts       录制、流程、证据与分析数据结构
scripts/verify.ts     独立闭环集成验证
docs/                 技术方案与本说明
data/                 本机运行数据（不纳入代码版本）
output/               验证结果与界面截图（不纳入代码版本）
