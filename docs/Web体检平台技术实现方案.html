Web 体检平台技术实现方案

版本：V1.0 评估稿 ｜ 日期：2026-09-16 ｜ 适用：公司内网 Web 系统人工录制与自动复检

本文是架构建议与实施计划，尚未开发或在实际业务系统中验证。当前项目目录未发现已有应用代码。正文、表格及打印文本统一使用黑色宋体。

结论：可以实现，建议建设为“人工探索录制 + 可编辑流程资产 + 容错自动回放 + 证据驱动 AI 分析”的 Web 体检平台。核心难点是人工操作录制的可靠性、异步接口与业务动作的关联、业务数据变化后的回放恢复，以及测试结论的证据约束。首版采用 Chromium、本机执行器与 Web 管理端，先打通一个真实业务模块的完整闭环。

一、产品定位与能力边界

你在平台点击“开始体检”，执行器打开独立的可见浏览器。你可以在地址栏输入公司项目地址，完成登录、菜单浏览、功能测试和完整业务流程。平台同步形成操作时间线、接口调用、前端日志和异常证据。结束后保存为可维护的流程，生成本次执行用例和体检报告；以后选择这个流程，平台按保存顺序自动执行并生成新的运行记录。

需求实现判断需要明确的边界
记录点击、输入、菜单和业务步骤可实现记录页面内动作及导航结果；地址栏逐键输入、操作系统原生文件窗口不是页面 DOM 事件。上传以文件选择结果和文件资源映射记录。
记录点击位置并回放可实现坐标用于证据与兜底；主回放依据元素定位和页面状态。窗口尺寸或布局变化时，单纯坐标回放不可靠。
记录全部接口并生成描述可实现浏览器观测范围内采集包括初始化、点击触发、轮询、失败请求与长连接；不等于服务器之间调用的全链路监控。请求体或响应体可能受流式、缓存、大小和协议限制，必须显式标记缺失。
Console、异常和警告可实现覆盖前端可观测信号；服务器内部异常栈需要后续接入后端日志或 APM。业务弹窗与 Toast 需要页面适配规则。
失败后继续下一条可实现，需场景和依赖设计独立步骤继续；依赖失败前置条件的步骤标记阻塞并跳过；恢复页面后执行下一独立场景。
AI 生成用例和报告可实现执行事实由采集器与断言提供；AI 生成描述、归类和分析，不把未执行功能写成通过，也不能凭一次正常响应证明业务正确。

本产品首期属于功能与稳定性体检。它不自动代表全功能覆盖、压力测试、安全渗透测试或后端服务全链路监控。覆盖范围应明确显示“本次实际访问的模块与执行的流程”；只有导入完整菜单或需求基线后，才有条件计算全系统覆盖率。

二、与参考方案的取舍

参考方案本项目建议原因
每次仅保留一个主请求保存所有观测到的调用，展示主请求、关联刷新、公共请求等分类查询成功后字典加载失败、保存成功后列表刷新失败，同样需要诊断。
丢弃初始化、轮询、长连接保留并单独分组；界面默认折叠低价值重复项监测大屏、告警系统中的轮询和推送属于重要业务链路。
不保留响应正文限额保存脱敏后的 JSON/文本；二进制保留元数据识别 HTTP 200 但业务码失败，以及登录失效却返回 HTML 等异常。
最近一次点击的固定时间窗归因多信号评分、多对多关联和“待确认归属”连续点击、异步延迟、请求并发和后台轮询容易被错误归到最后一次点击。
接口候选导入接口库流程资产、执行记录、接口目录与证据库联合管理核心目标是重复体检并比较结果，不只是收集接口定义。
远程 noVNC 作为唯一入口首版本机浏览器，后续支持远程浏览器工作台更符合你直接访问公司内网、登录和操作的使用方式。

推荐使用 TypeScript 贯通前端、服务端和 Playwright，减少事件结构和回放模型在不同语言间重复定义。首期采用模块化单体 API 加独立浏览器执行进程，无需一开始拆成多个微服务。

组件建议理由与后续扩展
前端React、Vite、TypeScript、shadcn/ui、Tailwind、Magic UI、Motion管理系统交互丰富；shadcn 提供基础组件，Magic UI 用于少量视觉表现，Motion 统一动效。
状态和接口TanStack Query、轻量客户端状态、表格虚拟滚动大量接口与日志分页读取，避免一次渲染整场录制数据。
后端NestJS + PostgreSQL + Prisma便于划分录制、执行、报告、模型配置和权限模块。
任务调度首期 PostgreSQL 任务表、租约、心跳和幂等键减少部署依赖；多执行节点与较大任务规模时再引入 Redis/BullMQ。
执行器Node.js + Playwright；每场体检独立浏览器上下文首期支持有桌面会话的 Windows 本机；团队版部署 Linux 远程执行节点。
证据存储受管本地目录起步，统一存储接口团队版替换为 S3 兼容对象存储，数据库只存索引和校验值。
报告导出在线报告、HTML、Excel 用例，后续 DOCX/PDF所有文档导出统一黑色宋体；PDF 导出环境需安装可用宋体并检查字体嵌入。

浏览器运行位置必须明确：普通 Web 前端不能直接启动用户本机的受控浏览器，需要已安装并配对的本机执行器。服务端启动的浏览器则位于服务器，若想直接操作它，需要远程桌面流。第一版支持管理端、API 和执行器同机运行；后续 API 集中部署，内网测试机运行执行器。

本机执行器使用主动出站连接和短时任务令牌，不开放无认证的远程调试端口。远程版使用 Linux 图形会话与 noVNC/WebSocket 或其他桌面流技术，嵌入的是受控桌面视图，不是把被测网站直接放进 iframe，以免受目标网站嵌入限制影响。远程执行机必须能访问目标网络。

四、人工操作录制设计

Playwright 官方提供 codegen 来生成操作脚本，可以作为原型验证和定位器参考；平台正式资产采用自有、版本化的动作模型，使用公开 API 采集与执行，避免依赖未承诺稳定的内部 recorder 接口。Trace 用于补充调试证据，不能替代人工操作记录库。参见 Playwright Test generator 与 Tracing API。

浏览器访问目标地址前，先注册网络、页面、新页签和上下文监听，再通过 addInitScript 与 exposeBinding 注入页面采集器。采集器在导航后的文档和 iframe 中初始化，处理 SPA 路由切换、弹窗、滚动容器以及 open Shadow DOM；跨域 frame、弹出页首屏事件和页面快速关闭需列入专项验证。

数据层记录内容
交互事件pointerdown/click/dblclick、输入与 change、键盘快捷键、提交、勾选、选择、滚动、必要的 hover、拖拽、导航、文件选择、下载和浏览器对话框。
页面语义菜单路径、面包屑、页面标题、页签、弹窗标题、控件角色与文本、表单标签、表格行上下文。
定位信息pageId、frame 路径、testId/role/name/label、作用域、稳定 CSS 候选、元素边界、点击相对坐标、视口大小与滚动位置。
时序和证据全局序号、时间戳、动作起止、关联截图、导航前后 URL、页面状态摘要、关联请求和日志 ID。
回放契约前置条件、输入变量、等待条件、后置断言、依赖步骤、失败策略、数据输出和恢复入口。

采集层保留必要的事件序列，编译层将同一输入框的连续文字输入合并为 fill 动作；Enter、Tab、组合键保留为 press。中文输入法以 compositionend/input 后的提交文本为依据，避免把拼音中间状态回放出来。对按键驱动的组件保留专用键盘序列，不能一律合并。

定位优先级建议为稳定 testId、role+name、label、受作用域限制的文本、稳定属性/CSS，最后才是校验视口和元素边界后的坐标。定位结果必须唯一；多个候选匹配时记录歧义，不能任意点击。closed Shadow DOM、Canvas/WebGL、复杂地图和定制拖拽列为适配对象，首版不承诺通用可靠回放。参见 Playwright Locators。

截图的时刻要如实描述：人工点击的 DOM 事件传给执行器后再截图，页面可能已经改变。因此人工录制采用“最近一次可用画面 + 事件时刻元素快照 + 动作后画面”，标明截图时间差；自动回放才可以在动作前主动截图。不承诺每个人工动作都有严格同步的前置截图。

录制控制支持“暂停全部采集”和“只暂停动作记录”两个明确模式，避免用户误以为暂停后不再记录网络。无论哪种模式，都在证据时间线上标注空档。用户可在录制中标记“新场景”“检查点”“此处应出现某文本”，停止后也可拆分合并场景。

五、网络、日志与业务归属

网络主采集使用 BrowserContext 范围的 request、response、requestfinished、requestfailed 等事件，覆盖上下文中的页面；页面侧附加 WebSocket 监听。Chromium 专属 CDP 用于补充 initiator、浏览器诊断、SSE 消息等能力，使用固定浏览器版本并做回归验证。Playwright 支持 HTTP(S)、XHR/fetch 和 WebSocket 的观测，见 官方网络文档；CDP 补充能力见 Network 协议。

请求元数据包括方法、完整 URL、查询参数、脱敏请求头和请求体、状态码、响应头、耗时、传输大小、资源类型、重定向链、缓存/Service Worker 标记、失败原因、page/frame、开始结束时间。每次调用均有独立 ID；“接口目录去重”仅发生在汇总视图，不能覆盖同一接口某一次失败的记录。

JSON/文本响应保存脱敏内容及摘要，建议单体默认上限 256 KB、可配置；大文件、二进制、下载保存类型、大小、校验值和受管附件索引。超限、无法读取、连接未结束或采集异常分别记录原因。WebSocket/SSE 保存连接生命周期、错误和消息计数，消息正文按配置限额保存；截断和丢失计数必须出现在报告中。

缓存、Service Worker、Worker、多页面启动时序和流式响应会影响观察结果。“全部接口”在验收中定义为指定浏览器上下文和明确采集范围内的调用覆盖，不宣称绝对零遗漏。默认保持被测系统的 Service Worker 行为，另提供诊断模式；禁用 Service Worker 会改变系统运行条件，不能悄悄启用。诊断模式及证据缺口应写入报告。

日志采集包括 console 各级别、pageerror、未处理 Promise rejection、资源加载失败、浏览器崩溃与关闭事件；应用内 Toast、Alert 和表单错误通过通用规则加项目适配器识别。采集字段包含级别、消息、来源位置、可用堆栈、时间和业务上下文。控制台对象序列化要限制深度、大小与循环引用，并先脱敏。参见 Page API。

HTTP 4xx/5xx 是有响应的 HTTP 请求，不一定触发 requestfailed；网络失败与 HTTP 错误必须分别判断。业务失败另按项目配置的 JSONPath、成功码、错误字段或内容类型规则识别，不能把所有系统都假定为 code=0。预期的 401 权限测试或主动中断请求也不能直接判为产品缺陷。参见 Request API。

接口描述与操作关联

建立三层索引：业务模块 → 操作步骤 → 请求实例，同时建立独立接口目录。同一个接口可以属于多个菜单，一个动作也可以触发多个接口；不能把每个接口固定归到唯一菜单。

设备管理 / 设备台账 / 点击“查询”
  ├─ 查询设备台账列表 → GET /api/devices?page=1
  ├─ 获取设备类型选项 → GET /api/device-types
  └─ 刷新在线数量 → GET /api/devices/online-count

告警管理 / 历史告警 / 点击“导出”
  ├─ 创建历史告警导出任务 → POST /api/alarm/export
  ├─ 查询导出任务进度 → GET /api/export/{taskId}
  └─ 下载历史告警文件 → GET /api/export/{taskId}/file

上述名称是示例，实际名称由页面语义、动作文本、请求结构、响应字段和可选 OpenAPI 描述共同生成。先用规则得到“菜单 + 动作 + 对象”的稳定名称，再让 AI 补充说明。每条关联保留匹配理由、置信度、规则/模型版本和人工修订历史。

归属评分综合同页面/frame、请求启动时刻、动作活跃区间、导航目标、可用 initiator、前后数据依赖和周期性特征。时间窗口可以作为候选筛选条件，但不能作为因果证明；新动作开始后，先前已经发起的慢请求仍归原动作。延迟请求、多个候选同分和异步任务保留候选关系或标记待确认。初始化和轮询无法归到具体动作时保留页面/场景级归属。

六、流程资产与容错回放

把录制结果保存成可编辑的流程定义，每次编辑发布新版本；每次复检生成独立运行实例并绑定具体版本。不要将历史报告、流程定义和最新执行结果混写在同一条记录里。流程编辑页支持修改定位器、变量、断言、超时、依赖、跳过策略、场景边界和恢复入口。

流程：设备管理体检 v3
  公共前置：打开环境 → 登录 → 确认首页
  场景 A：查询设备 → 校验列表
  场景 B：新增设备 → 提取 deviceId → 编辑该设备 → 清理测试数据
  场景 C：打开告警模块 → 查询历史告警 → 导出
  场景 D：返回首页 → 检查大屏关键区域

若 B 的“新增设备”失败：
  记录失败及证据 → 判断是否实际已创建 → 处理必要清理
  → 将依赖 deviceId 的编辑步骤标为 BLOCKED
  → 恢复到 C 的入口 → 继续执行告警场景

回放采用结构化动作解释器，每个动作拥有独立超时和结果记录。默认按原顺序调度；点击后等待目标状态、关键响应或断言成立，使用有上限的等待。带轮询或推送的系统不会长期网络静默，因此不能把 networkidle 当作每一步的通用成功条件。

情况处理策略
非关键独立步骤失败保存截图、接口、日志，标记 FAILED；下一步前置条件满足则继续。
创建数据、导航等关键前置失败依赖后续步骤标为 BLOCKED，并跳至下一个可恢复、独立的场景。
残留弹窗或页面偏离执行显式配置的关闭弹窗、返回入口、重新导航等恢复步骤，恢复动作单独记录。
登录过期执行登录前置或等待人工重新登录；超过等待时限后将依赖认证的场景标记阻塞，仍完成已有数据分析和报告。
浏览器崩溃重建上下文并验证认证与场景前置，只恢复可独立场景；不从任意半执行的写操作盲目续跑。
接口提交后超时先检查服务端可观察结果；新增、删除、下发等有副作用动作默认不自动重试，防止重复创建或重复执行。

建议步骤状态为 PASSED、FAILED、BLOCKED、SKIPPED、NEEDS_REVIEW；其中 PASSED 必须有明确检查条件，只有“点击完成且没有自动规则报错”的步骤应显示“执行完成，业务结果待确认”。运行状态与业务结论分离，例如运行 COMPLETED_WITH_ISSUES，并不意味着所有用例通过。

检查点保存 URL、已知页面状态、变量、认证引用和恢复操作，不是浏览器/服务器的任意状态快照，也不会撤销已经提交的业务数据。页面恢复与测试数据清理必须分别设计。用户可设置只读回放模式；涉及设备下发等动作，流程中应显式标记操作类别并按项目环境策略控制可执行范围。

账号、密码与动态值通过变量注入；运行时重新获得 Token。新增记录采用唯一测试标识，并从响应或页面提取实际 ID。日期、验证码、文件路径、下载目录、环境地址不能硬编码。验证码和 MFA 使用人工接管或测试环境既有机制，首版不实现自动破解。文件上传保存受管测试文件引用，不能只记录本机绝对路径。

七、AI 分析、用例与报告

原始采集证据
  → 脱敏与完整性检查
  → 确定性异常检测、重复聚合、业务上下文关联
  → 按场景/异常簇构建证据包
  → 模型生成结构化分析 JSON
  → Schema 校验、证据 ID 校验、状态一致性校验
  → 合并为可编辑的用例与体检报告

规则层先处理 HTTP 错误、业务码失败、网络失败、未捕获异常、断言失败、超时和性能阈值。AI 负责问题标题、模块说明、影响分析、可疑原因、定位建议和用例文字整理。请求、响应和 DOM 文本均作为不可信分析资料，模型不得执行其中的指令、外发数据或修改执行结果。

每个发现必须携带证据引用：runId、stepId、requestId、logId、截图与时间范围。报告区分“已观察事实”“推测原因”“建议检查项”；无法从前端证据确认的后端根因必须写成推测。相同堆栈或相同接口错误可聚合，但保留所有发生位置和次数。

用例字段包括编号、模块、标题、前置条件、测试数据、步骤、预期结果、实际结果、执行状态、证据和来源流程版本。预期结果优先来自用户配置、需求资料或明确断言；AI 推断的预期标为待确认，不能用本次实际输出反过来证明本次通过。由 AI 建议的补充测试用例归为“未执行”，与本次实际执行用例分开。

报告包含环境与版本、执行范围、已执行/阻塞/跳过统计、已验证通过率及分母、异常清单、接口情况、前端错误、慢请求、失败恢复过程、证据缺口、结论和复测建议。性能数据是本次会话的观察结果，标明样本数和采集开销，不替代负载测试。首页优先展示异常数量、覆盖情况与证据完整度；可解释的健康评分作为后续功能。

分析采用后台任务。模型超时、限流或不可用时，录制、回放和规则报告仍可完成，分析状态显示待重试；已产出的分段结果可复用。对证据内容哈希相同的分析可缓存，模型或提示词变化则建立新分析版本，保留原报告。

八、系统维护中的模型 API 配置

内置 DeepSeek、Qwen、GLM 三类厂商配置，以及自定义兼容服务。官方文档分别说明兼容接口接入能力：DeepSeek API、阿里云百炼、智谱开放平台。协议兼容不代表所有参数、结构化输出和图片输入能力完全相同，因此保留独立适配层与能力检测，不锁死模型名称。

配置组页面可维护内容
连接厂商、配置名称、Base URL、API Key、model ID、可选企业代理、超时。
能力文本/图片支持、结构化输出方式、上下文预算、最大输出、适用模型参数；依据配置或测试结果启用。
运行默认分析模型、项目覆盖配置、并发、限流、重试、预算上限、允许的备用服务。
分析规则提示词模板版本、异常等级规则、报告模板、分段大小、业务成功码规则。
数据边界允许送模的字段、正文与截图开关、脱敏规则、允许的模型服务地址。
验证和记录连接测试、最小分析样例测试、响应格式校验、调用耗时、Token 用量和失败原因。

配置测试成功后方可启用。API Key 只在后端加密存储，页面仅显示掩码；修改配置仅作用于新任务，历史运行保存不含密钥的配置快照。调用费用仅在存在有效价格配置或厂商计费数据时估算，不编造金额。备用模型只使用用户配置允许的服务。

外部模型只接收脱敏后的最小必要证据，不默认发送完整录屏、身份凭据或大批业务数据。截图可能包含人员、矿井和生产信息，应单独配置遮盖及送模开关；纯文本模型默认分析日志与语义摘要。支持后续切换到公司内网部署的兼容服务。

九、前端页面与视觉设计

设计方向为克制、清晰的工程工作台：浅灰背景、深色侧栏、白色内容面板、细边框、适量留白，使用单一蓝青色作为交互强调。首页适度突出品牌与体检入口，记录详情优先保证信息密度与定位效率。错误和警告同时使用图标与文字，不只依赖颜色。

一级页面核心内容与交互
体检首页项目和环境切换、“开始新体检”“选择流程复检”、最近运行、异常概况、历史趋势、执行器状态。
录制工作台顶部控制条；本机模式显示浏览器状态和实时画面预览，用户在独立浏览器操作；左侧业务场景树、中间操作时间线、右侧证据抽屉。
流程库流程版本、步骤编辑、变量和认证配置、断言、依赖、恢复入口、试跑与复制。
体检记录每次录制/复检的状态、环境、耗时、异常数；详情页联动步骤、请求瀑布图、Console、截图和分析结果。
问题中心问题聚合、首次/最近发现、严重程度、出现模块、忽略原因、修订与复测追踪。
历史档案冻结的报告与证据快照，基线版本、跨次对比、下载导出、保留期限；不与实时运行列表重复定位。
系统维护模型服务、项目环境、执行器、业务错误码、脱敏、存储保留、账号权限与审计。

shadcn/ui 承担导航、表格、表单、弹窗、抽屉和基础反馈；Magic UI 用于首页背景、少量数值与状态强调；Motion 负责抽屉、时间线、新增记录和页面切换过渡，支持减少动态效果。禁止在网络表格和长日志区域叠加持续动画，以免影响排查。三者的官方入口：shadcn/ui、Magic UI、Motion。

长列表采用服务端分页与虚拟滚动，详情按需加载；操作与请求可通过时间线相互定位。点击“查询设备台账失败”，应直接打开对应步骤、失败接口和截图，而不是要求用户从一堆 URL 中再次查找。

十、数据结构、接口与可靠性

核心实体职责
projects / environments / agents被测项目、环境地址、浏览器配置、执行器能力与在线状态。
flows / flow_versions / scenarios / step_definitions可复用流程、不可变发布版本、场景和步骤契约。
runs / step_executions一次人工录制或自动复检及其逐步执行事实、重试和恢复尝试。
events / network_calls / console_events带序号的采集事件、请求实例、日志与错误。
api_catalog / operation_request_links接口汇总目录与多对多业务归属，关联理由和置信度。
artifacts / findings / cases / reports文件索引、问题、执行用例、报告版本与证据引用。
model_profiles / analysis_jobs / audit_logs模型配置、分析任务、配置版本和操作审计。

事件至少包含 runId、agentId、pageId、frameId、sequence、eventType、agentTime、receivedAt、schemaVersion。单节点动作顺序以递增序号为主，浏览器时钟与执行器时钟建立偏差映射；不能单靠前端收包顺序推断行为先后。

建议接口分组为 /projects、/environments、/agents、/recordings、/flows、/runs、/artifacts、/findings、/reports 和 /settings/model-profiles；录制操作包括开始、暂停、继续、停止，执行包括开始、取消、人工接管和恢复；实时通道传递增量事件及任务状态。

执行器使用本地追加日志和上传确认序号，断线后续传，服务端按事件唯一键幂等写入。任务使用租约防止两个执行器重复领取，浏览器进程退出时已上传记录仍可查询。停止录制后进入 DRAINING，限时等待在途请求与文件写入；到期的长连接标为未结束，不无限等待。

AI 分析失败与浏览器运行失败分开记录。服务重启后将失去心跳的任务标为中断，保留证据；对副作用是否发生不明确的步骤不自动续跑。采集压力过大时先限制正文与预览频率，保留元数据并上报降级原因；如果仍发生事件丢失，必须在报告显示证据不完整。

凭据与证据分离：密码、Token、Cookie 使用密钥引用或短期加密认证状态，设置有效期；日志、请求正文与数据库持久化前完成脱敏。Playwright Trace、HAR、录像和 DOM 快照可能独立包含敏感数据，不能因为结构化日志已脱敏就视为安全。默认采用可控采集格式；原始 Trace/HAR 仅在受限诊断模式保存，禁止直接送模或随普通报告导出。

大附件和截图设置容量、保留期限与项目权限；删除证据后报告仍保留摘要和“附件已到期”的明确标记。租户/项目权限覆盖文件下载和实时控制，而不只覆盖列表页面。首期默认每个本机执行器一个交互录制任务，避免争抢同一桌面；后台复检并发数经实际资源测试后配置。

十一、分阶段实施与验收

阶段交付内容建议投入与退出标准
0. 技术验证选择一个有代表性的真实模块，覆盖登录、菜单、查询、新增、iframe/新页签之一和故意失败场景。3–5 个工作日量级；验证人工录制、接口归属、中文输入和失败后继续，记录实际限制后锁定范围。
1. 可用录制闭环管理端骨架、本机执行器、事件采集、接口与日志详情、历史运行、规则异常。约 2 周；可完成录制、查看业务描述、定位错误和留存证据。
2. 可维护的自动复检流程版本、变量、断言、场景依赖、恢复机制、登录和测试数据处理。约 2–3 周；故意失败的场景不阻断后面的独立场景，且不会误报通过。
3. AI 与报告三家模型配置、分析任务、证据校验、用例生成、在线报告与 Excel/HTML 导出。约 1–2 周；模型不可用仍保留规则报告，切换配置无需修改代码。
4. 加固与试用真实系统回归、断线续传、崩溃恢复、脱敏、数据保留、性能与界面打磨。约 1–2 周；满足下面的验收矩阵，处理试用反馈。

在 2 名熟悉 TypeScript/Playwright 的开发人员、有测试环境和测试支持、首期以标准 DOM 后台系统为主的前提下，可将约 6–9 周作为初步排期量级；这不是承诺工期，阶段有重叠，技术验证后应重新估算。复杂 Canvas、工业控件、远程桌面、多租户和更多浏览器作为后续增量评估。

验收主题可检查标准
动作覆盖受控测试页的点击、中文输入、快捷键、选择、导航、iframe 和新页签事件都有对应动作记录；支持范围外的控件有明确提示。
调用完整性用带唯一标识的测试后端请求台账核对浏览器可观测调用；初始化、并发、慢请求、失败、重定向、轮询和推送有记录，正文截断可追溯。
业务归属基于人工标注样本核验接口描述和归属；连续点击、延迟请求不强行错配，低置信度可修订并复用。
顺序与恢复正常流程按录制顺序执行；注入一步失败后下一独立场景仍实际执行，依赖步骤显示 BLOCKED，副作用步骤不盲目重试。
异常识别HTTP 500、网络断开、HTTP 200 业务失败、console.error、pageerror、业务弹窗均按对应类型显示；预期负向测试可配置正确判定。
证据与报告每个问题能跳转到证据；未执行和业务待确认项不计为通过；分析引用不存在的 ID 时被拦截。
模型配置三家适配器分别以实际有效账号验证，错误密钥、超时、限流及结构化输出失败不会破坏原始记录。
运行可靠性录制中断网、关闭浏览器、重启服务后已提交证据仍可查询；重复上传不产生重复事件；证据缺口可见。
敏感信息预置测试密码、Token 和 Cookie 不出现在普通数据库字段、日志、报告和送模包；单独验证截图与原始调试附件策略。
视觉与文档主要工作台在目标分辨率下不遮挡操作，长列表不卡住主界面；导出文档和用例为黑色宋体。

十二、首版范围建议

首版包括：Windows 本机可见 Chromium、Web 管理端、人工录制、请求和日志采集、接口业务描述、流程编辑与版本、场景级容错回放、三家模型可配置分析、历史档案、在线报告及 Excel/HTML 导出。实际开发从“登录 → 菜单 → 查询 → 新增 → 人为制造失败 → 下一场景继续 → 报告”这一条纵向闭环开始，再扩展页面和控件支持。

后续版本再加入远程浏览器内嵌、团队多执行器、复杂控件适配、可视化差异、完整 DOCX/PDF 模板、后端日志/APM 关联及计划任务。保留这些扩展接口，但首期不让它们阻塞核心价值验证。

进入开发前需要在技术验证中落实的输入是：一个可访问的典型测试工程、测试账号、代表性业务流程、部署机器网络条件，以及模型服务能否访问外网。这些输入用于收敛适配范围；本方案不预设已经完成这些现场验证。
